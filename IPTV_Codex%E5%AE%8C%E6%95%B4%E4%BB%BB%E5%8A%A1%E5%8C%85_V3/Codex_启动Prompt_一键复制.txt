我要做的是“杭州电信家庭高清 IPTV 自动订阅系统”，不是视频网站、电视播放器或代理服务器。

【真实使用环境】
- 电视：Redmi X65，已安装 TiviMate 免费版，只用一个在线 M3U 订阅。
- 宽带：杭州电信；开发电脑：Mac mini（macOS）。
- 不用 NAS、Docker、VPS、香港/国外代理，不修改 OpenClash，不搭建后台。
- 只需要 CCTV 和主要省级卫视，1080P 优先，最低 720P，绝对不要 360P。

【必须解决的旧项目问题】
以前我拿到的 51 台 IPTV 列表几乎完全无法播放，原因之一是把大部分频道固定选到了同一域名，没有真正检测视频流。另有浙江卫视地址可播约 24 秒后冻结：HLS 的 MEDIA-SEQUENCE 359977910 在多次请求中不增加，三个约 8 秒的分片一直重复。请务必把这一故障建立成可重复的单元测试，并确保失效源不能进入发布列表。不要因为 HTTP 200、URL 带 1080p、域名看起来正规就认定可用。

【交付结果】
1. Python 项目：解析 CCSH/IPTV、Oasisic-IPTV 等公开 M3U，标准化频道，安全去重、过滤错误来源。
2. 真实 HLS 验证：Master/Media Playlist、分片真实下载、直播进度推进、ffprobe 实际分辨率至少 720P、合理超时与并发限制。
3. 每频道最多 1 条主线 + 1 条独立来源的备用线。输出 live.m3u、backup.m3u、report.json。未通过检测的频道宁可缺席。
4. GitHub Actions 每天自动运行一次，异常时禁止覆盖上次成功版本；同一工作流发布到 GitHub Pages 的固定 HTTPS 地址。
5. 没有 NAS、Docker、服务器和代理依赖。支持 Mac 本地 dry-run，但不要求 Mac 常驻。
6. 自动化测试覆盖 24 秒冻结、短片段 404、伪装高清、VOD、频道名称混淆、异常更新回滚和 SSRF 防护。
7. README 提供所有运行、部署及 Redmi X65 + TiviMate 订阅步骤。
